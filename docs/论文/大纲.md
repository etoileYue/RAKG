# 第1章 绪论
重点回答“为什么要做这个课题”。
可写内容：
- 大模型问答虽然能力强，但存在幻觉、知识时效性不足、推理过程不透明等问题。
- 传统RAG能引入外部知识，但对实体关系、多跳推理、证据组织支持有限。
- 知识图谱结构化强、可解释性好，但单独用于问答时构建成本高、泛化能力有限。
- 因此，将知识图谱与RAG融合，构建一个兼顾准确性、可解释性和工程可落地性的问答系统，具有研究意义和应用价值。
- 研究内容可概括为：知识图谱构建、图谱增量融合、图谱检索问答、前后端系统实现与实验评测。
- **企业问答场景的数据特点（这一点具体写）**： 在企业问答场景中，企业的原始文档大多相比于一般的文档数据更加复杂。其信息密度大，实体密度高。同时存在大量的含义相似但表述略微不同的实体，因此需要做实体对齐及消歧方面的优化。

# 第4章 RAKG核心方法设计
这是全文核心，分数通常主要看这一章。
建议重点写你项目里已经实现的内容：
- 文本预处理：句子切分、`chunk_id`设计、句向量生成。
- 实体抽取：逐句NER，针对短句和指代句引入窗口补丁机制。
- 实体消歧：先基于向量召回候选，再通过LLM两轮判定，再做实体簇合并。
- 跨文档对齐：新文档实体与已有图谱实体做标准名对齐，保留别名映射。
- 关系抽取：围绕中心实体构建局部证据上下文，要求关系必须绑定证据来源。
- 图谱融合：统一为 `entities + relations + chunk_map` 结构，并进行实体归并与关系去重。
- 问答方法：问题实体抽取、图节点匹配、1到2跳邻域扩展、证据组织、最终答案生成。
这一章建议多放流程图、模块图、伪代码或关键公式。
